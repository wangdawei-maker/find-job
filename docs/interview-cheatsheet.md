## 二、项目介绍（30 秒 / 2 分钟）

### 30 秒版

## 三、架构与部署（高频追问）

| 问题 | 回答要点 |
|------|----------|
| 前后端怎么交互？ | 浏览器访问前端端口；**axios `baseURL`** 为 `/api`；路径写 **`/rag/...`** 等；**Nginx** 把 `/api` 转到 **`backend:8000`**。 |
| 为什么不是直接访问 8000？ | 页面在 **前端容器（Nginx）**；API 走 **同域反代**，少跨域、统一入口。 |
| `VITE_API_BASE_URL` 干啥？ | **构建时**写入前端的 API 根路径；与 **`baseURL` + 子路径** 拼成完整 `/api/...`。 |
| Docker Compose 起什么？ | **frontend + backend** 两个服务；可选提 **volume** 持久化数据。 |

---

## 四、后端技术栈（诚实版）

| 问题 | 回答 |
|------|------|
| 后端框架？ | **FastAPI**；**Uvicorn** 跑 ASGI。 |
| 为什么不是 LangChain 全家桶？ | 业务是 **固定 API 流程**；**httpx** 调 LLM、**LC 只做 Embedding** 即可，易调试、依赖少。 |
| 数据库？ | **SQLite**，MVP / 单机；量与并发上来再考虑 **PostgreSQL** 等。 |
| 对话 vs 向量？ | **DeepSeek** 走 **httpx**；**Embedding** 走 **OpenAIEmbeddings**（两套配置），任务不同、成本不同。 |

## 五、RAG 设计（按真实代码说）

| 环节 | 本项目做法 | 可补「若升级」 |
|------|------------|----------------|
| **切分** | **固定字符窗口**（约 150 字 + 重叠），非语义切分 | 按段落/Markdown/语义切 |
| **向量** | 每块 **embedding**，维度截断/填充到固定维，存 **SQLite JSON** | pgvector、向量库 |
| **召回** | **全库 chunk 点积打分**，排序 **Top-K**（如面试 **top_k=3**） | FAISS/专用索引加速 |
| **重排** | **未做** 独立 rerank | Cross-Encoder / 业务 rerank |
| **进模型** | 拼成 **`[序号] 标题(来源)\n正文`**，放入 **user 消息**「可参考知识片段」 | 可调 system/user 分工、token 截断 |

**一句话**：MVP **检索 + 拼接 prompt**；**无 rerank**；效果与规模上去再迭代。

## 六、困难与排查（STAR，选 2 条熟记）

每条：**现象 → 原因 → 动作 → 结果**。

1. **Docker Hub / 镜像拉取超时** → 换 **阿里云制品中心** 或自建构建；**pip** 换 **国内 PyPI 镜像**。  
2. **前端 build 失败（rolldown/绑定）** → **Node ≥20.19** 满足 **engines**；否则可选依赖装不全。  
3. **接口 404** → **`baseURL` 已是 `/api`** 时路径不要再带 **`/api`**，避免 **`/api/api/...`**。  
4. **防火墙** → 放行 **5173**（及需要的 **8000**）；与域名解析不是一回事。

## 七、边界与「邻居技术」（被问「为什么不用 X」）

| 对方提 | 你怎么答 |
|--------|----------|
| Redis | 单机 MVP **未用**；**缓存/会话/限流** 场景可引入。 |
| FAISS / Chroma | 当前 **规模小、全表扫**；量与延迟上来再上 **索引/向量库**；FAISS 偏 **加速检索**，Chroma 偏 **存+查一体**。 |
| PostgreSQL / MySQL | SQLite 够用；**多写、高可用、复杂查询** 再迁 **服务端库**；**pgvector** 是 **PG 的向量扩展**。 |
| K8s | **Compose** 单机够用；多实例与编排再上。 |
